# 已确认需求

两台 Jetson Orin NX 16GB。编码端为本机，USB 摄像头已插入；解码端已通过192.168.50.2接入，编码端有线192.168.50.1。网线直连传码流，同一 Wi-Fi 用于管理。

第一版：DCVC-UF HT-S，640×360，30fps，端到端延迟目标不超过 500ms，须实测验收，不允许静默降分辨率。缩放保持比例，必要时补边。仅视频。

Gradio 集中控制，两路预览。启动脚本打开浏览器，点击开始才采集。暂停停止采集与编解码，保留最后画面；继续从实时画面恢复并重置必要状态。结束释放资源、保留统计，可再次开始；退出关闭服务。参数修改应用后重启流。

指标：采集、编码、解码、浏览器实际显示 FPS（需实际观测，不用推送次数冒充）、压缩码率、丢帧和注明范围的延迟。初版 QP 控制，目标 Mbps 自动控制留待后续。手动保存参数和统计，默认不保存视频。设备缺失显示明确状态并支持重新检测。本机编码测试与双机模式分开。

先检查环境、验证 HT-S 真实码流编码和性能，后续做界面和双机联调。测试视频可用于摄像头缺席时的验证。代码保持必要模块边界，不预造扩展框架。

已阅读 Ponytail full：复用现有代码，最小完整实现，保留关键校验和验证。两端已使用Miniforge独立项目环境，未替换系统Torch/CUDA。
