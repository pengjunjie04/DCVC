# Jetson DCVC Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Run a Chinese Gradio controller and validate actual HT-S bitstream coding on the encoder Jetson.

**Architecture:** Background Python worker, bounded capture queue, upstream codec adapter, validated TCP transport and separate preview. Independent decoder entry point.

**Tech Stack:** Miniforge Python 3.10, NVIDIA Torch CUDA 12.6, DCVC-UF HT-S, OpenCV, Gradio.

**Spec:** docs/superpowers/specs/2026-10-29-demo-design.md

## Global Constraints

- Preserve system CUDA/Torch. Store code under the Desktop project directory.
- 640x360, target 30fps, target end-to-end latency <=500ms; no claimed pass without measurement.
- Eight-frame HT-S chunks and actual entropy-coded bytes; no codec substitution.
- Camera and second Jetson absent; disclose untested acceptance items.

## Review Focus

- Stop/pause while codec initializes must not leave camera or worker running.
- Invalid/unbounded network lengths or metadata must be rejected before allocation.
- Missing camera, checkpoint or extension must produce useful recoverable errors.
- Frame counters must not confuse preview updates with display or codec FPS.
- Slow codec must bound capture backlog; resume must refresh codec state.
