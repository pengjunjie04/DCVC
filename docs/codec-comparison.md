# DCVC-RT 与 H.264/H.265 的对比

本页包含两部分证据：解码端页面中的**实时同源画面/链路对比**，以及 `tools/compare_codecs.py` 在单台 Jetson Orin NX 16GB、25W 下的**离线同质量 PSNR 对比**。前者回答“同一时刻三种链路看起来怎样、延迟和码率是多少”，后者回答“匹配 DCVC 重建质量时 H.264/H.265 需要多少码率”。两者不能互相替代。

## 实时同源对比

编码端勾选“实时 H.264/H.265 对比”后，同一帧 RGB 输入会同时送入三个编码路径：

- DCVC-RT HT-S，经项目 TCP 端口 `9860` 发往解码端；
- NVENC H.264，经 `9861` 发往解码端；
- NVENC H.265，经 `9862` 发往解码端。

解码端由 NVDEC 分别解码 H.264/H.265，转换成 BGRx 后编码成 JPEG，再通过 `/dev/shm/dcvc-hw-h264.frame` 和 `/dev/shm/dcvc-hw-h265.frame` 交给网页进程。编码端页面只显示原始输入；解码端页面显示重建画面、H.264 重建和 H.265 重建。H.264/H.265 共用编码端设置的硬件目标码率，DCVC 仍使用界面上的 QP。

实时指标口径：

- **码率**：对应 NVENC 或 DCVC 实际发送载荷，不含 TCP/IP 包头和显示 JPEG 返回链路；
- **端到端**：采集时间到本机 NVDEC 完成解码并生成 JPEG 的时间，不含浏览器绘制、摄像头曝光和屏幕扫描；
- **吞吐**：最近 2 秒解码端实际生成画面的帧率。

因此实时页适合检查同源画质、断流和链路时延，但**不是等质量比较**。DCVC 的 QP 与硬件编码器的目标 kbps 没有统一质量基准，不能仅凭同一时刻的画面或码率数字断言谁的压缩效率更高。实时链路也可在系统 Python 下单独复现：

```bash
python3 tools/hw_stream_worker.py decoder --bind 192.168.50.2
python3 tools/hw_stream_worker.py encoder --peer 192.168.50.2
```

正常使用时不需要手动运行这两个进程，`./start_decoder.sh` 和 `./start_encoder.sh` 会随服务管理。

### 实时实测记录

2026-11-04 在编码端 `192.168.50.1`、解码端 `192.168.50.2` 上完成 15 秒连续采样。两端均为 25W；摄像头以 YUYV 640×480@30 输出，保持比例补边到 640×360；三路共用同一帧输入，DCVC 使用 QP32，硬件编码器目标 300kbps。

| 路径 | 编码吞吐中位数 | 解码吞吐中位数 | 实测码率中位数 | 编码采集→编码完成 | 解码采集→JPEG 完成 |
|---|---:|---:|---:|---:|---:|
| H.264 NVENC/NVDEC | 30.05fps | 30.21fps | 298.5kbps | 12.3ms | 4.6ms |
| H.265 NVENC/NVDEC | 30.09fps | 30.18fps | 300.4kbps | 13.4ms | 5.4ms |

两路硬件连接全程保持，实际码率都接近目标值。这个短场景中 H.264 的实测码率和时延略低，H.265 没有表现出明显优势；360p 简单场景不应据此推断 H.265 在所有内容上更差。两组“采集→解码”数值使用跨机时钟校准，适合观察两路相对变化，不作为物理屏幕或曝光到显示的验收值。同期 DCVC 页面预览中位数 30.5fps，采集→canvas 中位数 465.7ms、p95 481.0ms；该显示口径包含浏览器绘制和 JPEG 预览 IPC，不能与表中硬件解码时延直接相减。

实时证据见 [`reports/realtime-hardware-comparison-25w.json`](../reports/realtime-hardware-comparison-25w.json)。该记录不是等质量 PSNR 对比；压缩效率结论仍使用下方离线同质量结果。

## 离线同质量方法

- 输入为公开 OpenCV `vtest.avi`，SHA256 `45cddc9490be69345cbdab64ca583be65987e864ca408038e648db99e10516cf`；源片 768×576、10fps。测试统一缩放并补边到 640×360，按 30fps 换算吞吐和码率。
- 所有编码器使用完全相同的 640 帧参考内容。DCVC-RT 使用本仓库官方 HT-S 权重、QP32，排除 3 个预热组；H.264/H.265 使用 Jetson NVENC、CBR、`preset-level=1`、`iframeinterval=30`，目标码率分别为 32/64/128/256/512 kbps。
- 硬件编码/解码速度由 GStreamer pad probe 计时，排除进程启动；编码从编码器输入首帧计到输出最后一帧，速度解码从解码器输入首帧计到 BGRx 转换输出最后一帧。质量路径先落盘再与同一 BGR 参考计算 8-bit RGB PSNR。
- DCVC 使用 `tools/benchmark.py` 的独立编码器/解码器状态，计时边界包含项目输入准备、GPU 拷贝、颜色转换、熵编解码和同步，不包含文件读取、TCP 或浏览器。
- 整个测试不打开摄像头、不保存视频或画面，只保存统计；开始和结束时均检查 `oc1/oc2/oc3_event_cnt`，三项均为 0。

## 离线实测结果

DCVC-RT QP32 在 640 帧上得到 **32.99 dB、42.7 kbps、编码 90.7fps、解码 67.1fps**。硬件编码器的全部测量点如下：

| 编码器 | 目标 kbps | 实际 kbps | PSNR dB | 编码 fps | 解码 fps |
|---|---:|---:|---:|---:|---:|
| H.264 | 32 | 55.0 | 24.86 | 1091.0 | 591.9 |
| H.264 | 64 | 65.0 | 25.73 | 949.5 | 574.4 |
| H.264 | 128 | 121.0 | 28.69 | 1012.5 | 584.3 |
| H.264 | 256 | 251.6 | 31.89 | 915.2 | 605.7 |
| H.264 | 512 | 503.5 | 34.97 | 1020.5 | 728.9 |
| H.265 | 32 | 38.8 | 24.82 | 1008.2 | 718.0 |
| H.265 | 64 | 59.6 | 26.06 | 975.0 | 620.4 |
| H.265 | 128 | 120.0 | 29.09 | 959.0 | 723.7 |
| H.265 | 256 | 250.7 | 31.90 | 1147.6 | 715.6 |
| H.265 | 512 | 505.9 | 34.73 | 1044.6 | 615.3 |

在 PSNR 32.99 dB 处对相邻实测点做实际码率的对数插值：

| 编码器 | 同质量码率 | 相对 DCVC-RT |
|---|---:|---:|
| DCVC-RT HT-S QP32 | 42.7 kbps | 1.0× |
| H.264 | 322.2 kbps | 7.5× |
| H.265 | 328.2 kbps | 7.7× |

也就是说，在这段公开视频和该质量点上，DCVC-RT 使用的码率约为 H.264/H.265 的 13%。代价是速度：本次 DCVC-RT 的编码/解码处理速度约为 90.7/67.1fps，明显低于硬件 ASIC 编解码器，但仍高于单路 30fps 的处理需求。速度结论不等同于双机端到端延迟结论。

## 解释边界

- 这是单段场景、单模型变体、DCVC 单 QP 点的结果。等质量码率只在 H.264 的 251.6–503.5 kbps、H.265 的 250.7–505.9 kbps 区间内插值得到，不能外推为完整率失真曲线。
- PSNR 不是感知质量指标，也未评估运动、遮挡、低照度和摄像头噪声。公开视频的分数不能当作真实摄像头场景的质量承诺。
- DCVC 与硬件编码器的计时边界并不完全相同：前者是项目 Python/CUDA 处理路径，后者是 GStreamer 硬件插件路径；因此本页用速度说明处理余量，不把跨实现 fps 差直接当作模型核心 kernel 性能比。
- 本轮只做单机顺序对比，不含网络传输、双机调度和显示链路；这些实时指标仍以双机报告为准。

原始证据：[`reports/codec-comparison-25w.json`](../reports/codec-comparison-25w.json)。

复现：

```bash
python3 tools/compare_codecs.py --frames 640 \
  --bitrates 32,64,128,256,512 \
  --output reports/codec-comparison-25w.json
```

脚本需用系统 Python 运行，因为 Jetson 的 GStreamer Python 绑定不在项目 `.env` 中。
